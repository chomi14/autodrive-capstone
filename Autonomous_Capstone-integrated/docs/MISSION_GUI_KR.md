# 통합 미션 신호등 표시와 GUI 정리안

## 반영한 표시

[Seyeon 77d357c](https://github.com/chomi14/autodrive-capstone/commit/77d357ccc349da4896822c41f3248bc5e8d244f3)의
신호등 상태 패널을 로컬 장애물 회피 + 신호등 통합 미션에 맞춰 적용했다.
`mission_bbox_only.launch.py`, `mission_bbox_size.launch.py`의 기존
`Mission Tuner`와 `Mission Debug View`에서 볼 수 있다.

- 신호등 색상, `LIGHT ACTION: STOP / SLOW / GO`, 빨강 정지 유지 여부
- 빨강·초록 연속 확인 횟수와 필요한 횟수
- 목표 차선, 자동 전환 쿨다운, `L` 수동 전환 안내
- 판정 대상에서 제외된 신호등 bbox는 회색으로 표시
- DRIVING/FPS/조향/속도 및 BEV 보정 요약은 카메라 밖 상단 띠에 표시
- 신호등 박스에 `TL#0` 등의 번호와 대표 픽셀 위치를 표시하고 상단에 같은 번호의 원본 crop 확대 표시
- 각 bbox의 전체 평균 RGB, 대표 픽셀 RGB/HSV, 빨강/초록/노랑 비율, S/V 통과 비율 표시
- bbox 크기/위치 제외, S/V 통과 픽셀 없음, 색상 비율 부족 등 Unknown 원인과 현재 임계값 표시

RGB는 0~255, HSV는 OpenCV 기준 H 0~179와 S/V 0~255다.
대표 픽셀은 S/V 임계값을 통과한 픽셀 중 최빈 Hue에 속한 중간 밝기의 픽셀이다.
통과 픽셀이 없으면 가장 밝은 픽셀을 대신 보여준다. 실제 선택 위치는 카메라의 작은 십자로 표시한다.
전체 평균은 신호등 하우징의 검정색 영향을 받을 수 있으므로 대표 픽셀 값과 함께 확인한다.
색상 수치는 선·글씨·차선 마스크를 그리기 전 원본 영상에서 측정한다.
상단 카드는 최대 4개이며 전체 bbox 수치는 Tuner 상세 목록에서도 볼 수 있다.

상태 띠를 영상 위에 추가하므로 카메라/BEV 영상 영역을 가리지 않는다.
`GO`는 신호등 판단이 주행을 허용한다는 뜻이며, 실제 출발 승인·출력은 기존
ARM/직렬 명령 상태에서 확인한다. 초록이 보여도 확인 횟수가 부족하면
`GREEN / STOP / RED LATCH: ON`으로 표시된다.

구현은 `skku_track_drive_pkg/traffic_light_display.py`이며 기존 미션 상태를
읽어 그리기만 한다. W/S/L 동작은 기존 통합 미션을 사용한다. 별도 신호등 노드나 창은 추가하지 않았다.

## 신호등 위치 조건 (2026-10-30 수정)

`traffic_max_bottom_y` 슬라이더 기본값은 **60**이다. 원본 카메라 기준 bbox 하단 Y가
`60 이하`이고 폭이 `traffic_min_width` 이상인 신호등만 색상/정지 판단에 사용한다.
좌표 기준은 640×480이며 다른 해상도에서는 비례 환산한다. 화면 상단 패널 높이는 좌표에 포함하지 않는다.

- 하단 Y > 60: 제외. RGB/HSV는 계속 표시하며 `bbox bottom exceeds max Y` 사유를 표시한다.
- 하단 Y <= 60: 유효. 빨강이 기본 3프레임 연속 확인되면 정지한다.
- 정지 후 bbox가 사라져도 정지를 유지하며, 유효한 초록이 기본 3프레임 연속 확인되면 해제한다.
- `wait_for_green=1`이면 시작부터 초록 확인까지 대기한다.

이전 `traffic_min_bottom_y`는 제거했다. 기존 저장 YAML에 이 항목이 있으면 로더가 이를 무시하고
새 최대값 기본값 60을 사용한다. 새 항목이 함께 있으면 새 값을 우선한다. GUI에서 P로 저장하면
새 파라미터 이름으로 저장된다. 값이 클수록 더 넓은 Y 범위를 허용하고, 작을수록 위쪽 bbox만 허용한다.
실제 정지선 위치와 제동 거리에 맞는 값은 주행 시 조정해야 한다.

## 현재 창 구성

기본 GUI·디버그를 켠 실제 차량 미션 실행 기준으로 총 7개다.
`sensors_only`/`dry_run`에서는 출발 승인 창이 빠진다.

| 창 | 역할 |
|---|---|
| Mission Tuner | 상태·로그·저장 안내 + 상단 Obstacle Cut (Y px) 슬라이더 |
| Mission Debug View | 카메라 + BEV + 주행/미션 표시 |
| Mission Tuner Controls 1 | 속도·조향·차선 처리 등 11개 조절 |
| Mission Tuner BEV Source Points | 보정점 좌표 8개 |
| Mission Tuner Controls 2 | 영상 지연 표시 기준·신호등 설정 12개 |
| Mission Tuner Controls 3 | 초록·노랑 HSV 범위 4개 |
| vehicle_start_gate | 캘리브레이션·출발 승인 |

`track_tuner_node.py`가 조절 항목을 12개 단위로 분할하고,
BEV 보정점을 별도 창으로 만들기 때문에 창 수가 늘어난다.
장애물 Y는 작은 별도 창에서 찾기 어려워 메인 창 상단으로 옮겼다.
GUI 표시는 `Obstacle Cut (Y px)`, 실제 ROS/저장 파라미터는 기존 `obstacle_near_y`다.
범위는 0~480이며, 값이 작을수록 영상 위쪽의 더 먼 장애물부터 회피 대상으로 본다.

## 권장 정리안 — 아직 미적용

평소에는 **모니터 + 기본 조절 2개**, 필요할 때 **고급 조절 1개**를 연다.

1. **통합 모니터:** 카메라/BEV, 신호등 패널, 목표 차선, 쿨다운,
   실제 명령 PWM, READY/ARM 상태와 최근 정지 사유를 한 창에 배치한다.
   현재 Tuner 상태 창과 Debug View를 합친다.
2. **기본 조절:** 속도·Stanley/heading gain·lookahead·장애물 Y처럼
   현장에서 자주 조절하는 항목을 모은다.
3. **고급 조절:** BEV/ROI, 차선 처리, 신호등/HSV를 페이지별로 전환한다.
   현재 Controls 2/3와 BEV 창을 대체하고 평소에는 숨긴다.
4. **출발 승인 창:** READY/캘리브레이션 상태를 통합 모니터에 연결한 뒤
   `drive_arm_node`의 표시만 `show_window=false`로 숨긴다.
   승인 노드·키 전달·heartbeat 처리는 계속 실행한다.

현재는 조절 창 하나를 닫아도 전체 튜너 종료와 정지 요청으로 이어진다.
따라서 창 정리는 단순히 X로 닫는 방식 대신, 설정 페이지/숨김 기능과
창 종료 처리를 함께 수정해야 한다.

## 확인

- 기존 미션·장애물 회피·L 키·정지 이력 검사 65개 통과
- 여섯 신호등 상태 및 폭 320/640/1280에서 헤드리스 렌더링 확인
- 입력 영상과 미션 상태가 렌더링으로 변경되지 않는 것 확인
- 실차 주행과 실제 데스크톱 창 배치는 이번 검증에 포함하지 않음
